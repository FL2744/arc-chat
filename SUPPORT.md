# ARC Chat support and escalation

Use the narrowest support owner for the problem.

## ARC Chat application problems

Examples: the packaged app does not start, a button throws an ARC Chat error before reaching ARC, the UI is unreadable, a local recovery state is wrong, or a reproducible ARC Chat regression occurs.

1. Run **Run diagnostics** and export the diagnostic report.
2. Remove anything you do not want to share, even though the report is designed to exclude credentials/chat/notebook contents.
3. Report the ARC Chat issue to the repository/project maintainers with the app version/build, operating system, exact action, error code, and recovery text.

Never attach API keys, passwords, Duo codes, browser cookies, or private research data to a public issue.

## ARC / HPC / Open OnDemand / scheduler problems

Examples: allocation access, queue behavior, Slurm jobs, ARC storage, ARC-hosted LLMs, Open OnDemand, or cluster-side failures.

Use Virginia Tech Advanced Research Computing support. Current ARC documentation links to office hours, consultations, and its help request path from the ARC documentation home page.

## Account / Duo / VPN / general VT IT problems

Examples: VT account/password, Duo lockout/device configuration, or general university IT access.

Use Virginia Tech 4Help. ARC's own FAQ also directs account/Duo problems to 4Help.

## Outages

Before treating an unreachable ARC service as an ARC Chat defect, check normal VT network/VPN access and the relevant Virginia Tech/ARC service status/maintenance information. ARC Chat deliberately does not bypass VPN, MFA, allocation policy, or scheduler controls.
